# Schema definition and type inference

## Table declaration

Declare every table with `pgTable(name, columns, extraConfig?)` from
`drizzle-orm/pg-core`:

```ts
import { pgTable, uuid, text, integer, timestamp, boolean } from "drizzle-orm/pg-core";

export const users = pgTable("users", {
  id: uuid("id").primaryKey().defaultRandom(),
  name: text("name").notNull(),
  email: text("email").notNull().unique(),
  age: integer("age"),
  isActive: boolean("is_active").notNull().default(true),
  createdAt: timestamp("created_at").notNull().defaultNow(),
});
```

- Pass the snake_case DB column name as the first argument to every column
  builder even when it matches the TS key; do not rely on implicit naming.
- Use `uuid(...).defaultRandom()` for externally exposed primary keys,
  `serial(...)` only for internal/legacy-style auto-increment ids.
- Chain `.notNull()` before `.default(...)`/`.defaultNow()`, and put
  `.primaryKey()` directly on the id column rather than in `extraConfig`
  unless the key is composite.

## Column type cheat sheet (PostgreSQL)

| Need | Column builder |
|---|---|
| Short/medium text | `text()` (unbounded) or `varchar({ length })` when a DB-level cap matters |
| Whole number | `integer()`, `bigint({ mode: "number" \| "bigint" })` for values beyond 32-bit |
| Exact decimal (money, quantities) | `numeric({ precision, scale })` — never `real`/`doublePrecision` for money |
| Approximate float | `real()`, `doublePrecision()` |
| Boolean flag | `boolean()` |
| Point in time | `timestamp({ withTimezone: true })` — default to `withTimezone: true` unless the domain is explicitly timezone-naive |
| Calendar date only | `date({ mode: "date" })` |
| Structured/opaque data | `jsonb<Type>()` — prefer over `json()` for indexing/query support |
| Fixed set of values | `pgEnum` (see below) |
| Identity | `uuid().defaultRandom()` or `serial()`/`bigserial({ mode: "bigint" })` |

## Constraints and indexes

Use the table's third argument (a callback returning an array) for
multi-column constraints and indexes:

```ts
import { pgTable, uuid, text, index, uniqueIndex, foreignKey } from "drizzle-orm/pg-core";

export const posts = pgTable("posts", {
  id: uuid("id").primaryKey().defaultRandom(),
  authorId: uuid("author_id").notNull().references(() => users.id),
  slug: text("slug").notNull(),
}, (table) => [
  uniqueIndex("posts_slug_idx").on(table.slug),
  index("posts_author_id_idx").on(table.authorId),
]);
```

- Use `.references(() => otherTable.column)` inline for a simple single-column
  foreign key; use the `foreignKey({ columns, foreignColumns })` helper in the
  array form only for composite foreign keys.
- Add an explicit index for every foreign key column and every column used in
  a frequent `where`/`order by` — Drizzle does not create these automatically.
- Name every index explicitly (`"<table>_<columns>_idx"`); do not rely on
  drizzle-kit's autogenerated name, since renaming a column later would
  otherwise silently rename the index.

## Enums

```ts
import { pgEnum, pgTable, uuid } from "drizzle-orm/pg-core";

export const orderStatus = pgEnum("order_status", ["pending", "paid", "shipped", "cancelled"]);

export const orders = pgTable("orders", {
  id: uuid("id").primaryKey().defaultRandom(),
  status: orderStatus("status").notNull().default("pending"),
});
```

Declare `pgEnum` once per logical enum, at module scope in the same file as
its primary table, and reuse the same enum value across every table that
needs it — never redeclare an equivalent enum with a different name.

## Multiple schemas

Use `pgSchema(name)` to namespace tables per bounded context/tenant instead of
prefixing table names by hand:

```ts
import { pgSchema, serial, text } from "drizzle-orm/pg-core";

export const billing = pgSchema("billing");

export const invoices = billing.table("invoices", {
  id: serial("id").primaryKey(),
  amount: text("amount"),
});
```

## Type inference

Never hand-write a row type or insert DTO for a Drizzle table:

```ts
export type User = typeof users.$inferSelect;
export type NewUser = typeof users.$inferInsert;
```

- `$inferSelect` reflects exactly what a `select()` returns (nullable columns
  become `| null`).
- `$inferInsert` reflects what `insert().values(...)` accepts (columns with a
  `default`/`defaultNow`/`defaultRandom` become optional).
- Export both types next to the table so callers import `{ users, User,
  NewUser }` from the same module instead of redefining the shape.
