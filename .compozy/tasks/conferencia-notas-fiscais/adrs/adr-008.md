# ADR-008: Leitura de código de barras via biblioteca open-source baseada em WASM

## Status

Accepted

## Date

2026-08-16

## Context

O produto precisa ler códigos de barras 1D (o padrão usado em caixas de produto) pela
câmera do celular, funcionando de forma confiável tanto em Android quanto em iPhone. A
pesquisa de mercado feita na fase de PRD confirmou que o iOS Safari não tem suporte
nativo confiável à `BarcodeDetector` API (Shape Detection API), então uma solução
puramente baseada em API nativa do navegador não cobre iPhone. O usuário optou por uma
solução open-source sem custo de licenciamento, em vez de um SDK comercial.

## Decision

O scanner de código de barras usa uma biblioteca open-source baseada em WebAssembly
(ZXing-wasm), acessando a câmera via `getUserMedia`/`MediaStream` e decodificando frames
no cliente. A leitura roda inteiramente no navegador (sem depender de API nativa
específica de plataforma), garantindo comportamento consistente entre Android e iPhone.
A integração fica isolada num hook `useBarcodeScanner` no `frontend`, para poder trocar
de biblioteca no futuro (ex: migrar para um SDK pago) sem reescrever as telas que a
consomem.

## Alternatives Considered

### Alternative 1: `BarcodeDetector` nativo com fallback

- **Description**: Usar a API nativa do navegador quando disponível (majoritariamente
  Android/Chrome), com fallback para uma lib JS em navegadores sem suporte.
- **Pros**: Melhor performance onde a API nativa existe.
- **Cons**: Mantém dois caminhos de código para testar e depurar; iOS Safari cai sempre
  no fallback de qualquer forma, tornando a otimização condicional pouco proveitosa dado
  que grande parte do público-alvo (iPhone) nunca usa o caminho nativo.
- **Why rejected**: Adiciona complexidade sem benefício consistente, já que o
  comportamento em iOS — a plataforma mais restritiva — é o mesmo nas duas opções.

### Alternative 2: SDK comercial (ex: Scanbot)

- **Description**: Usar um SDK pago especializado em leitura de código de barras em
  condições difíceis.
- **Pros**: Maior taxa de acerto em códigos borrados/mal impressos/pouca luz, suporte
  oficial.
- **Cons**: Custo de licenciamento recorrente.
- **Why rejected**: O usuário optou explicitamente por começar sem custo de licença,
  reavaliando no futuro se a taxa de leitura da lib open-source se mostrar insuficiente
  em uso real.

## Consequences

### Positive

- Sem custo de licenciamento.
- Comportamento único e testável em todas as plataformas, sem branching por
  capacidade do navegador.

### Negative

- Taxa de leitura pode ser inferior a um SDK comercial em condições ruins (baixa luz,
  código amassado/borrado) — mitigado parcialmente pela UI dando feedback claro quando a
  leitura falha, permitindo tentar de novo ou usar seleção manual (US-006).

### Risks

- Risco: desempenho de decodificação WASM em aparelhos Android mais antigos pode ser
  mais lento. Mitigação: reavaliar biblioteca/SDK após uso real na loja, já isolada
  atrás do hook `useBarcodeScanner`.
