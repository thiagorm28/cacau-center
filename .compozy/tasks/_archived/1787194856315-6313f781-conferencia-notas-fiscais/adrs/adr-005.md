# ADR-005: Busca de nota por número de faturamento via API interna Cacau Show, sem QR code

## Status

Accepted

## Date

2026-08-16

## Context

A primeira versão do PRD assumia que o operador buscaria a nota digitando a chave de
acesso de 44 dígitos da NFe (padrão nacional), com a opção adicional de escanear o QR
code impresso no DANFE para preencher esse código automaticamente. O usuário corrigiu
essa premissa: a busca será feita contra uma API própria da Cacau Show (rota a ser
fornecida antes do TechSpec), e o identificador usado nessa busca não é a chave de
acesso de 44 dígitos, e sim o número de faturamento da nota — na nota de exemplo,
`004005647`, um número bem mais curto que a chave de acesso completa.

Como o QR code impresso no DANFE tradicionalmente carrega a chave de acesso da NFe (não
o número de faturamento), a opção de leitura de QR code na tela de entrada da nota
deixou de fazer sentido: não há, confirmado pelo usuário, um código escaneável no
documento que corresponda ao número de faturamento.

## Decision

A busca de nota passa a ser feita exclusivamente por digitação manual do número de
faturamento da nota (ex: `004005647`), usado diretamente como parâmetro de busca na API
interna da Cacau Show. A opção de escanear QR code na entrada da nota é removida do
produto — não existe mais leitura de código/QR nesse ponto do fluxo. A leitura por
câmera do produto fica restrita exclusivamente à etapa de bipagem de caixas.

O formato exato de validação do número de faturamento (quantidade de dígitos, uso de
zeros à esquerda) depende do contrato real da API da Cacau Show, ainda não fornecido —
tratado como Open Question até a fase de TechSpec.

## Alternatives Considered

### Alternative 1: Manter chave de acesso de 44 dígitos com QR code opcional

- **Description**: Versão original do PRD, buscando via chave de acesso pública da NFe
  com opção de leitura de QR code do DANFE.
- **Pros**: Padrão nacional, funcionaria com qualquer provedor de consulta de NFe, não
  só uma API interna da Cacau Show.
- **Cons**: Não reflete a forma real como a busca será feita (API interna da Cacau Show
  usando número de faturamento); exigiria suporte a leitura de QR code sem necessidade
  real, já que o número de faturamento não está codificado nesse QR.
- **Why rejected**: O usuário confirmou que a busca real usa o número de faturamento
  contra uma API própria da Cacau Show, tornando a chave de acesso de 44 dígitos e o QR
  code do DANFE desnecessários para esse fluxo.

## Consequences

### Positive

- Entrada da nota fica mais simples e rápida para o operador (número mais curto que a
  chave de acesso de 44 dígitos).
- Reduz escopo técnico: não é mais necessário implementar leitura de QR code na tela de
  entrada de nota, apenas na etapa de bipagem de caixas.

### Negative

- Acopla a busca de nota especificamente à API interna da Cacau Show — o produto deixa
  de ser genérico o suficiente para funcionar com qualquer provedor público de consulta
  de NFe por chave de acesso.

### Risks

- Risco: sem conhecer ainda o contrato exato da API da Cacau Show, o formato de
  validação do número de faturamento (dígitos, zeros à esquerda) pode mudar quando a
  rota for fornecida. Mitigação: manter a validação de formato no TechSpec flexível até
  a confirmação do contrato real da API.

## Implementation Notes

Formato de validação do campo, contrato da API e tratamento de erros específicos ficam
a cargo do TechSpec, condicionados à rota que o usuário ainda vai fornecer.
