# ADR-002: Senha inicial previsível com troca obrigatória no primeiro login

## Status

Accepted

## Date

2026-08-19

## Context

O pedido original define a senha inicial de um usuário recém-cadastrado como
`CPF@dataDeNascimento` (ex.: `12345678900@15031990`). Tanto CPF quanto data de
nascimento são dados quase públicos (vazamentos, registros públicos, redes sociais),
então essa senha é adivinhável por quem souber os dois dados da pessoa — um padrão
reconhecido como fraco para uma senha permanente.

## Decision

A senha `CPF@dataDeNascimento` é usada apenas como senha *inicial* (ou de reset). No
primeiro login com essa senha, o sistema obriga o usuário a definir uma nova senha
antes de liberar qualquer outra tela — não é uma sugestão, é bloqueante. O mesmo vale
sempre que o admin reseta a senha de alguém (ADR referenciado no PRD, seção Business
Rules): o reset volta a conta para o estado "senha inicial, troca obrigatória
pendente".

## Alternatives Considered

### Alternative 1: Senha inicial permanente, sem troca obrigatória

- **Description**: `CPF@dataDeNascimento` continua válida indefinidamente, sem forçar
  troca.
- **Pros**: Mais simples de implementar; nenhuma tela nova de "trocar senha".
- **Cons**: Mantém uma senha adivinhável válida para sempre, para todo funcionário —
  colega de trabalho, ex-funcionário ou qualquer um com acesso a nome/CPF/data de
  nascimento consegue logar. Contradiz a prática de mercado para esse padrão de senha
  inicial.
- **Why rejected**: O custo de implementar a tela de troca obrigatória é pequeno
  perto do risco de manter senhas adivinháveis permanentes para todos os funcionários.

## Consequences

### Positive

- Nenhuma conta fica protegida apenas por uma senha derivada de dados públicos por
  mais que o tempo mínimo necessário até o primeiro login.
- O mesmo mecanismo cobre tanto o cadastro inicial quanto o reset feito pelo admin.

### Negative

- Exige uma tela/fluxo novo de "definir nova senha", que bloqueia o restante da
  aplicação até ser concluído.

### Risks

- Se o usuário nunca fizer o primeiro login, a conta fica indefinidamente com a senha
  previsível — mitigado por ser o mesmo risco de qualquer conta nunca acessada, não
  agravado por esta decisão.

## Implementation Notes

Regras de força da nova senha (tamanho mínimo etc.) ficam a critério do TechSpec.
