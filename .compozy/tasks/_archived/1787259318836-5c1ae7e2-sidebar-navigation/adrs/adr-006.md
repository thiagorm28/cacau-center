# ADR-006: No new frontend dependencies — icon, animation, and swipe gesture are hand-rolled

## Status

Accepted

## Date

2026-08-20

## Context

The drawer needs a trigger icon, a slide-in/out transition, and swipe-to-close. The frontend's `package.json` has no icon library, no animation library (no Framer Motion), and no gesture library (no `@use-gesture/react`, no Hammer.js) — every existing visual and interaction pattern in the codebase (including `Dialog.tsx`, which has no transition or gesture handling at all) is built from plain Tailwind classes and native React/DOM APIs. This is a mobile-only PWA, where bundle size directly affects install/update size and load time.

## Decision

No new npm dependency is added for this feature.

- **Icon**: the trigger button uses an inline SVG (hamburger/menu glyph), matching the pattern of zero external icon usage elsewhere in the codebase.
- **Animation**: the drawer's open/close transition uses a CSS `transform: translateX(...)` with `transition`, toggled by the component's open-state class — no animation library.
- **Swipe-to-close**: implemented with native `onTouchStart`/`onTouchMove`/`onTouchEnd` handlers on the drawer panel, tracking horizontal drag distance and committing to open/closed based on a distance threshold, with the panel's `transform` following the finger during the drag for immediate visual feedback.

## Alternatives Considered

### Alternative 1: Add a gesture library for swipe-to-close

- **Description**: Introduce `@use-gesture/react` (or similar) to handle the swipe interaction, keeping icon and animation hand-rolled.
- **Pros**: Handles edge cases (velocity-based flicks, multi-touch, pointer vs. touch normalization) more robustly than a hand-rolled implementation.
- **Cons**: Adds a new dependency and its transitive weight for a single, single-purpose gesture in a mobile PWA where install size matters; the interaction needed (one-directional drag-to-dismiss on one element) is simple enough to hand-roll correctly.
- **Why rejected**: User chose not to introduce any new dependency for this feature.

## Consequences

### Positive

- No bundle size increase, no new dependency to keep patched/updated, consistent with the codebase's existing zero-icon-library, zero-animation-library posture.

### Negative

- The hand-rolled swipe handler must be implemented and tested carefully (threshold tuning, drag-cancel behavior) since it doesn't get a library's edge-case handling for free.

### Risks

- Touch gesture edge cases (e.g., a swipe that starts on an interactive nav item vs. empty panel space) need explicit test coverage; flagged in the TechSpec's test plan.

## Implementation Notes

Threshold and easing values are implementation detail decided at build time, not fixed here.
