# ADR-002: Consolidate logout into the navigation drawer, removed from per-screen headers

## Status

Accepted

## Date

2026-08-20

## Context

`LogoutButton` is currently placed manually in the header slot of 7 separate screens (`frontend/src/features/auth/LogoutButton.tsx`, imported individually in each). There is no central place logout lives — every screen owner has to remember to add it. Market research confirms the common convention for admin/internal tools: logout sits at the bottom of the navigation drawer/sidebar, separated from primary navigation, rather than repeated per-screen.

## Decision

Logout moves into the navigation drawer (ADR-001) as a single, bottom-anchored action, visually separated from the feature navigation links. The standalone `LogoutButton` instances in 6 of the 7 screen headers are removed — logout becomes reachable only through the drawer on those screens.

**Exception**: the mandatory password-change screen keeps its own standalone `LogoutButton` in its header, unchanged from today. Since the drawer never appears on that screen (ADR-001, US-006), removing its logout button too would leave a user with no way to end the session while a password change is pending — a regression from current behavior. This screen is therefore the one place in the UI that still has a screen-owned logout control.

## Alternatives Considered

### Alternative 1: Keep logout in both places

- **Description**: Leave the existing per-screen `LogoutButton` in place and additionally add it to the drawer.
- **Pros**: Zero regression risk; fastest path with an extra shortcut.
- **Cons**: Two sources of truth for the same action, contradicts the goal of consolidating navigation/account actions into one predictable place, keeps header clutter on every screen.
- **Why rejected**: User explicitly chose consolidation over duplication.

## Consequences

### Positive

- One canonical place for account actions; screen headers regain space for screen-specific content.
- Matches the market convention (logout grouped with navigation, not scattered per-screen).

### Negative

- Every screen currently importing `LogoutButton` directly changes its header composition — a cross-cutting edit across 7 screens.

### Risks

- If the drawer trigger is ever hidden or broken on a screen, that screen loses its only logout path. Mitigated by ADR-001's rule that the trigger is global (all authenticated screens except mandatory password change), and by keeping a dedicated logout button on the one screen (mandatory password change) that intentionally has no drawer.

## Implementation Notes

Product-level only; removal of the 7 inline imports and the exact component wiring belong to the TechSpec.
